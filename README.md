# MYTRIP

주말 여행 일정, 장소, 주차 정보와 쇼핑리스트를 한 화면에서 관리하는 정적 웹사이트입니다.

```bash
npm install
npm start
```

여행, 일정, 장소, 쇼핑리스트, 예약과 준비물은 현재 브라우저의 `localStorage`에 저장됩니다.

## 장소와 일정 편집

- 날짜 탭 아래의 **+ 일정 추가**에서 장소 이름이나 주소를 검색해 바로 타임라인에 배치합니다.
- OpenStreetMap 검색 결과를 선택하면 장소 보관함 저장과 일정 연결을 한 번에 처리합니다.
- 타임라인에서 순서 변경, 방문 완료, 건너뜀, 편집을 바로 실행합니다.
- 일정 사이의 이동수단·이동시간을 기록하고 하루 총 체류·이동시간을 확인합니다.
- 앞 일정의 종료·이동 예상과 다음 시작 시간이 겹치면 부족한 시간을 경고합니다.
- 숙소처럼 반복할 일정은 **일정 복제** 후 날짜와 시간만 바꿀 수 있습니다.
- 별도의 `장소 고르기` 단계는 사용하지 않습니다. 일정 추가 창에서 장소 선택까지 한 번에 처리합니다.
- 검색 서비스에서 찾을 수 없는 장소만 후보 장소의 수동 등록 기능으로 보관할 수 있습니다.
- 한국 장소는 네이버 지도·티맵, 해외 장소는 Google Maps로 연결됩니다.

직접 등록한 장소와 일정은 브라우저에 보관됩니다. 다른 기기와 자동 동기화되지는 않습니다.

## 예약·준비물과 백업

- **여행 준비**에서 숙소·항공·식당·교통·체험 예약의 날짜, 상태, 예약번호와 링크를 보관합니다.
- 준비물에 담당자를 지정하고 완료 상태를 확인할 수 있습니다.
- **여행 목록 → 현재 여행 내보내기**에서 장소, 일정, 쇼핑, 환율 저장값, 예약과 준비물을 JSON 파일로 저장합니다.
- 다른 기기에서는 **여행 가져오기**로 해당 파일을 불러올 수 있습니다. 가져온 여행은 기존 여행을 덮어쓰지 않고 새 여행으로 만들어집니다.

## 여러 여행 관리

- 상단의 **여행 목록**에서 제목, 목적지, 국가, 시작일, 종료일을 입력해 여행을 만듭니다.
- 여행을 선택하면 해당 여행의 장소·일정·쇼핑리스트만 불러옵니다.
- 여행 정보 수정, 복제, 삭제를 지원합니다.
- 여행 목록은 날짜를 기준으로 **여행 중 / 다가오는 여행 / 지난 여행**으로 자동 분류하며, 지난 여행도 삭제하기 전까지 일정과 쇼핑 기록을 그대로 열 수 있습니다.
- 새 여행은 기존 예시 일정이 섞이지 않은 빈 상태로 시작합니다.
- 공유 Google Sheets의 2026년 11월 27일~30일 홋카이도 일정은 `홋카이도 3박 4일 여행`으로 한 번 자동 등록됩니다. 시트의 본 일정, 미배치 대안 장소, 쇼핑 전용 탭, 확정·예정 예약과 확인사항을 각각 해당 화면에 분리해 반영했습니다.
- 식당 대안은 준비물과 분리한 **못 갔을 때 대안**에서 날짜별로 확인하고 바로 일정에 추가할 수 있습니다.
- 쇼핑 전용 탭의 상품 80개와 셀에 배치된 상품 사진 52개를 그림 중심 행 기준으로 XLSX에서 추출해 함께 제공합니다.
- Google 쇼핑 검색과 Open Food Facts 공개 식품 DB 검색을 분리합니다. Google은 실제 판매 결과를 새 탭에서 보여주며, 공개 식품 DB 결과만 앱 입력 폼으로 가져옵니다. Google 공식 검색 API 설정 전에는 Google 결과를 앱으로 자동 수집하지 않습니다.
- 쇼핑 항목은 현지 가격과 최신 환율 기준 한국 가격을 함께 표시합니다. 상품 추가·수정에서 사진 파일을 직접 선택하거나 이미지 URL을 입력할 수 있고, 편집창에서 사진 교체·삭제도 지원합니다.
- 기기에서 선택한 사진은 최대 640px JPEG로 축소해 여행 데이터에 저장되며 내보내기와 클라우드 스냅샷에도 포함됩니다. 원본 시트에 사진이 없는 항목은 사진 미등록 아이콘으로 구분합니다.

## 모바일 화면

- 620px 이하에서는 일정·쇼핑·여행 준비·장소·여행 목록이 하단 고정 메뉴로 표시됩니다.
- 현재 보고 있는 영역을 메뉴에서 강조하며 iPhone 안전 영역을 포함해 본문이 메뉴 뒤에 가리지 않도록 여백을 확보합니다.
- 320~430px 휴대폰과 가로 모드 검사는 `npm run test:mobile`로 반복할 수 있습니다.

## 제품 구조

- 모바일 주 메뉴는 **홈 / 일정 / 쇼핑 / 준비 / 여행 목록**입니다.
- 홈에서 출발 상태, 전체 일정, 예약 확정, 남은 확인, 가격 미입력, 대안 수와 날짜별 일정을 확인합니다.
- 저장 장소는 일정에 아직 넣지 않은 후보 보관함이며 일정 화면의 **후보 장소**에서 접근합니다.
- 데이터별 책임과 전체 사용자 흐름은 [`docs/product-redesign-v1.md`](./docs/product-redesign-v1.md)에 정리했습니다.
- 스크립트 시작 순서, 저장소 키의 소유권과 기능 간 데이터 흐름은 [`docs/architecture.md`](./docs/architecture.md)에 정리했습니다.

## Supabase 준비

클라우드 동기화를 연결할 때는 Supabase Dashboard의 **SQL Editor**에서 [`supabase/schema.sql`](./supabase/schema.sql)을 한 번 실행합니다. 이 스키마는 로그인한 사용자가 자신의 여행 스냅샷만 읽고 수정하도록 RLS를 적용합니다. 브라우저에는 publishable key만 사용하며 Secret 또는 `service_role` 키를 넣지 않습니다.

**여행 목록 → 기기 간 동기화**에서 이메일 로그인 링크를 받아 현재 여행을 저장하거나 다른 기기의 저장본을 불러옵니다. Supabase Authentication의 URL Configuration에는 실제 배포 주소를 Redirect URLs로 등록해야 로그인 링크가 앱으로 돌아옵니다.
