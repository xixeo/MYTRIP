# MYTRIP 제품 구조 v1

## 목표

사용자는 여행 전에 무엇이 확정됐고 무엇을 확인해야 하는지 알고, 여행 중에는 다음 일정과 지도를 두 번 이내의 동작으로 열 수 있어야 한다.

## 모바일 정보 구조

1. 홈: 여행 상태, 일정 수, 예약 확정, 남은 확인, 가격 미입력, 날짜별 요약
2. 일정: 날짜별 확정 흐름, 이동 구간, 충돌, 지도
3. 쇼핑: 상품 사진, 매장, 수량, 현지 가격, 원화 환산, 구매 상태
4. 준비: 예약 상태·번호와 실제 행동 과제
5. 여행 목록: 여행 전환, 백업, 클라우드 동기화

저장 장소는 주 메뉴가 아니다. 일정에 넣기 전 후보 보관함으로 일정 화면에서 접근한다. 대안 플랜은 일반 후보와 달리 특정 일정 실패 시 교체하기 위한 콘텐츠다.

## 데이터의 단일 책임

| 데이터 | 책임 | 넣지 않는 정보 |
| --- | --- | --- |
| Trip | 제목, 국가, 기간 | 개별 일정 |
| Place | 이름, 주소, 지도, 영업 메모 | 방문 날짜와 시간 |
| ItineraryItem | 날짜, 시간, 체류, 상태 | 예약번호, 상품 가격 |
| TravelLeg | 이전 일정에서 이동수단·시간 | 방문 정보 |
| Alternative | 대체 상황, 날짜, 대안 장소 | 준비물 |
| Reservation | 확정 상태, 번호, 링크 | 별도 중복 일정 |
| ChecklistItem | 사용자가 해야 할 확인·준비 | 음식점 후보 |
| ShoppingItem | 사진, 상품, 매장, 통화, 가격 | 방문 일정 |

교통편 자체가 예약된 버스·열차·항공이면 일정 항목이 될 수 있다. 일정 사이의 단순 이동 예상은 TravelLeg로만 기록한다.

## 핵심 흐름

- 새 일정: 일정 추가 → 저장 후보 선택 또는 새 장소 생성 → 시간·이동 입력 → 타임라인 확인
- 대안 사용: 대안 플랜 → 일정에 추가 → 날짜·시간 결정
- 현지 사용: 홈 → 오늘 날짜 → 다음 장소 → 지도
- 쇼핑: 상품 확인 → 현지 가격 입력 → 원화 환산 → 구매 완료
- 여행 준비: 홈의 남은 확인 → 예약/준비 화면 → 완료 처리
